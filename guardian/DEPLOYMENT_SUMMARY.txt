THREADING MODEL
================

Main Thread (UI)
    ↓
GuardianMonitor (runs in QThread)
    ├── Continuously scans every 30 seconds
    ├── Emits signals to main thread
    ├── Updates status indicator
    ├── Populates anomalies table
    ├── Displays predictions
    └── Logs diagnostic events

Signal-Slot Architecture:
  - health_changed(HealthStatus, str)
  - anomaly_detected(AnomalyReport)
  - snapshot_ready(IntegritySnapshot)
  - prediction_ready(List[str])

KNOWN LIMITATIONS
=================

- Cannot detect file corruption within files (only hash mismatch)
- Cannot distinguish git-tracked from unauthorized changes (uses hash)
- Requires read permissions on all monitored files
- Network drives significantly slower (increase scan_interval)
- No network communication (all monitoring is local)
- Cannot auto-fix file corruption (requires human restore)


PERFORMANCE METRICS
====================

Baseline Performance:
  - Startup time: <1 second
  - Scan interval: 30 seconds (configurable)
  - Scan duration: <5 seconds (depends on file count)
  - Memory usage: ~50-100 MB (including Qt)
  - CPU usage: <5% during scans, <1% between scans

For Large Deployments (100K+ files):
  - Increase check_interval to 60+ seconds
  - Reduce monitored files to critical paths only
  - Use separate fast-scan vs. full-scan modes
  - Consider GPU acceleration for hashing
